# 기능 명세서: 할 일 CRUD

**기능 브랜치**: `001-todo-crud`

**작성일**: 2026-09-16

**상태**: 초안

**입력**: 사용자 설명: "사용자가 할 일을 추가하고, 목록을 확인하고, 완료 여부를 토글하고, 삭제할 수 있는 기능이 필요하다. 할 일에는 제목(필수)과 완료 여부가 있다."

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 새 할 일 추가하기 (우선순위: P1)

사용자가 해야 할 일의 제목을 입력하고 등록하면, 해당 할 일이 목록에 기록된다.

**이 우선순위인 이유**: 이 기능이 이 기능 전체 가치의 출발점이다 — 할 일을 추가할 수 없으면 보거나, 완료 처리하거나, 삭제할 대상 자체가 없다.

**독립적으로 테스트하는 방법**: 제목을 입력해 등록한 뒤, 해당 항목이 "미완료" 상태로 목록에 나타나는지 확인하는 것만으로 완전히 테스트할 수 있다.

**인수 시나리오**:

1. **Given** 할 일 목록이 비어 있는 상태에서, **When** 사용자가 제목 "우유 사기"를 입력하고 등록하면, **Then** "우유 사기"라는 제목의 새 항목이 "미완료" 상태로 목록에 나타난다.
2. **Given** 사용자가 제목을 비워두거나 공백만 입력한 뒤 등록을 시도하면, **When** 시스템이 입력값을 검증할 때, **Then** 항목이 생성되지 않고 제목이 필수임을 알리는 검증 메시지가 사용자에게 표시된다.

---

### 사용자 스토리 2 - 할 일 목록 확인하기 (우선순위: P2)

사용자가 자신이 추가한 모든 할 일과 각각의 완료 여부를 확인하기 위해 목록을 연다.

**이 우선순위인 이유**: 사용자는 자신의 작업을 추적하고 처리하려면 목록을 볼 수 있어야 하며, 이는 할 일 추가(P1) 다음으로 가장 필수적인 기능이다.

**독립적으로 테스트하는 방법**: 여러 개의 할 일 항목을 미리 준비해 둔 뒤, 목록을 확인할 때 모든 항목이 올바른 제목과 완료 상태로 표시되는지 확인하는 것만으로 완전히 테스트할 수 있다.

**인수 시나리오**:

1. **Given** 완료/미완료가 섞인 여러 개의 할 일 항목이 존재하는 상태에서, **When** 사용자가 목록을 확인하면, **Then** 모든 항목이 제목과 현재 완료 상태와 함께 표시된다.
2. **Given** 할 일 항목이 하나도 존재하지 않는 상태에서, **When** 사용자가 목록을 확인하면, **Then** 오류나 빈 화면 대신 "항목 없음"을 알리는 빈 상태 화면이 표시된다.

---

### 사용자 스토리 3 - 완료 여부 토글하기 (우선순위: P3)

사용자가 할 일을 끝냈을 때 완료로 표시하거나, 다시 처리해야 할 경우 미완료로 되돌린다.

**이 우선순위인 이유**: 진행 상황을 추적하는 것은 할 일 목록의 핵심 목적이지만, 이는 이미 항목이 존재하고(P1) 눈에 보여야(P2) 의미가 있다.

**독립적으로 테스트하는 방법**: 기존 항목 하나를 선택해 상태를 토글한 뒤, 표시되는 상태가 바뀌고 그 상태가 유지되는지 확인하는 것만으로 완전히 테스트할 수 있다.

**인수 시나리오**:

1. **Given** 미완료 상태인 할 일 항목이 있을 때, **When** 사용자가 이를 완료로 표시하면, **Then** 해당 항목의 상태가 "완료"로 바뀌고 목록에 즉시 반영된다.
2. **Given** 완료 상태인 할 일 항목이 있을 때, **When** 사용자가 이를 미완료로 표시하면, **Then** 해당 항목의 상태가 다시 "미완료"로 바뀌고 목록에 즉시 반영된다.

---

### 사용자 스토리 4 - 할 일 삭제하기 (우선순위: P4)

사용자가 더 이상 필요 없는 할 일 항목을 제거하여 목록을 깔끔하게 유지한다.

**이 우선순위인 이유**: 정리 기능은 유용하지만, 할 일을 추가하고 확인하고 완료 처리하는 핵심 흐름에 비하면 중요도가 가장 낮다.

**독립적으로 테스트하는 방법**: 기존 항목 하나를 선택해 삭제한 뒤, 해당 항목이 더 이상 목록에 나타나지 않는지 확인하는 것만으로 완전히 테스트할 수 있다.

**인수 시나리오**:

1. **Given** 목록에 할 일 항목이 존재할 때, **When** 사용자가 이를 삭제하면, **Then** 해당 항목은 즉시 목록에서 제거되며 더 이상 조회할 수 없다.

---

### 사용자 스토리 5 - 중요도 지정 및 변경하기 (우선순위: P5)

사용자가 할 일마다 중요도(높음/중간/낮음)를 지정해 어떤 일이 더 중요한지 한눈에 구분하고, 필요하면 나중에 다시 바꾼다.

**이 우선순위인 이유**: 핵심 CRUD 흐름(추가/조회/완료/삭제)이 이미 갖춰진 뒤에 추가되는 부가 기능이며, 중요도가 없어도 할 일 관리 자체는 가능하다.

**독립적으로 테스트하는 방법**: 할 일을 추가할 때 중요도를 지정(또는 생략)해 기본값이 적용되는지 확인하고, 기존 항목의 중요도를 변경한 뒤 그 값이 즉시 반영·유지되는지 확인하는 것만으로 완전히 테스트할 수 있다.

**인수 시나리오**:

1. **Given** 할 일을 새로 추가할 때, **When** 사용자가 중요도를 "높음"으로 지정해 등록하면, **Then** 새 항목이 "높음" 중요도로 목록에 나타난다.
2. **Given** 할 일을 새로 추가할 때, **When** 사용자가 중요도를 지정하지 않고 등록하면, **Then** 새 항목의 중요도는 기본값인 "중간"으로 설정된다.
3. **Given** 이미 존재하는 할 일 항목이 있을 때, **When** 사용자가 해당 항목의 중요도를 다른 값으로 변경하면, **Then** 변경된 중요도가 즉시 반영되고, 목록에 표시되던 다른 항목들의 순서는 바뀌지 않는다.

---

### 예외 상황

- 사용자가 빈 문자열이나 공백만으로 이루어진 제목을 등록하려고 하면 어떻게 되는가? 시스템은 이를 거부하고 항목을 생성하지 않아야 한다(FR-002 참고).
- 사용자가 이미 삭제된 할 일 항목을 토글하거나 삭제하려고 시도하면 어떻게 되는가(예: 오래된 화면을 보고 있는 경우)? 시스템은 나머지 목록을 손상시키지 않으면서 명확한 오류를 표시하거나 조용히 무시(no-op) 처리하는 등 우아하게 처리해야 한다.
- 목록에 항목이 매우 많을 경우 어떻게 되는가? 목록은 오류 없이 모든 항목을 표시할 수 있어야 한다(이 기능에서는 구체적인 성능 목표를 정의하지 않는다).
- 사용자가 "높음/중간/낮음" 세 가지가 아닌 값으로 중요도를 지정하려고 하면 어떻게 되는가? 시스템은 이를 거부하고 항목을 생성/변경하지 않아야 한다(FR-010 참고).

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 사용자가 제목을 입력하여 새로운 할 일 항목을 추가할 수 있도록 해야 한다.
- **FR-002**: 시스템은 항목을 생성하기 전에 제목이 비어 있지 않도록 요구해야 한다(빈 문자열이나 공백만으로 이루어진 값은 거부한다).
- **FR-003**: 시스템은 모든 할 일 항목을 목록으로 표시해야 하며, 각 항목은 제목, 완료 상태, 중요도를 함께 보여주어야 한다.
- **FR-004**: 시스템은 사용자가 기존 할 일 항목의 완료 상태를 "완료"와 "미완료" 사이에서 토글할 수 있도록 해야 한다.
- **FR-005**: 시스템은 사용자가 기존 할 일 항목을 삭제하여 목록에서 영구적으로 제거할 수 있도록 해야 한다.
- **FR-006**: 시스템은 할 일 항목(제목과 완료 상태 포함)을 저장하여, 세션이 바뀌어도 계속 유지되도록 해야 한다.
- **FR-007**: 시스템은 새로 생성된 할 일 항목의 완료 상태를 기본값으로 "미완료"로 설정해야 한다.
- **FR-008**: 시스템은 존재하지 않는 할 일 항목에 대한 토글이나 삭제를 허용해서는 안 되며, 이러한 시도에는 다른 항목의 상태를 손상시키지 않고 적절한 오류를 반환하거나 아무 동작도 하지 않아야 한다.
- **FR-009**: 시스템은 사용자가 할 일 항목에 중요도(높음/중간/낮음 중 하나)를 지정할 수 있도록 해야 하며, 지정하지 않으면 기본값으로 "중간"을 사용해야 한다.
- **FR-010**: 시스템은 사용자가 기존 할 일 항목의 중요도를 생성 이후에도 다른 값으로 변경할 수 있도록 해야 하며, "높음/중간/낮음" 세 가지 값이 아닌 값은 거부해야 한다.
- **FR-011**: 시스템은 목록에 표시되는 할 일 항목의 순서를 중요도에 따라 바꾸지 않아야 한다(중요도는 표시 목적으로만 사용되며 정렬 기준이 아니다).

### 핵심 엔티티

- **할 일(Todo)**: 사용자가 추적하고자 하는 하나의 작업을 나타낸다. 속성: 제목(텍스트, 필수, 비어 있지 않아야 함), 완료 여부(불리언, 기본값 false), 중요도(높음/중간/낮음 중 하나, 기본값 "중간", 생성 이후에도 변경 가능). 각 할 일 항목은 개별적으로 토글하거나 삭제할 수 있도록 고유하게 식별 가능해야 한다.

## 성공 기준 *(필수)*

### 측정 가능한 성과

- **SC-001**: 사용자는 새 할 일을 추가하는 동작을 시작한 뒤 5초 이내에 해당 항목이 목록에 나타나는 것을 확인할 수 있다.
- **SC-002**: 사용자가 추가한 할 일 항목의 100%가 별도의 특별한 조작(일반적인 화면 이동 외) 없이 목록에 표시된다.
- **SC-003**: 사용자는 단 한 번의 조작(예: 클릭 또는 탭 한 번)으로 할 일 항목의 완료 상태를 토글할 수 있다.
- **SC-004**: 삭제된 할 일 항목의 100%가 삭제 직후 목록에서 사라지며, 삭제된 항목이 다시 나타나는 사례가 없다.
- **SC-005**: 사용자가 애플리케이션을 닫았다가 다시 열어도 할 일 항목과 그 완료 상태는 검증 사례의 100%에서 정확하게 유지된다.
- **SC-006**: 사용자는 할 일 항목의 중요도를 단 한 번의 조작으로 변경할 수 있으며, 변경 후에도 목록 내 다른 항목들의 순서는 그대로 유지된다.

## 가정

- 이 애플리케이션은 단일 사용자용이며, 이 기능에서는 인증, 권한 부여, 다중 사용자 데이터 분리를 다루지 않는다.
- 할 일 항목은 애플리케이션 재시작이나 페이지 새로고침 이후에도 유지되도록 내구성 있게 저장되어야 한다(이 프로젝트가 스토리지 기반이라는 성격과 일치한다).
- 이 기능에서 할 일 항목은 제목, 완료 상태, 중요도(높음/중간/낮음)를 가지며, 기한, 카테고리, 설명 등은 포함하지 않는다. 중요도는 표시 목적으로만 사용하며 목록 정렬 기준으로 사용하지 않는다(FR-011).
- 제목이 비어 있거나 공백만으로 이루어진 경우를 거부하는 것 외에, 제목 길이에 대한 별도의 상한은 두지 않는다.
- 삭제는 즉시 이루어지며 영구적이다. 휴지통, 되돌리기(undo) 같은 기능은 요구되지 않는다.
- 서로 다른 할 일 항목 간에 제목이 중복되는 것은 허용된다. 제목의 고유성은 요구되지 않는다.
