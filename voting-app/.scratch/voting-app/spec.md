# 동아리 투표 앱

Status: ready-for-agent

## Problem Statement

동아리 회장은 동아리원들에게 질문 하나를 던지고, 각자 선택지 중 하나를 골라 의견을 모은 뒤 결과를 확인하고 싶다. 지금은 이를 위한 전용 도구가 없어 단톡방 투표나 손으로 세는 방식에 의존하고, 중복 참여를 막거나 결과를 깔끔하게 보여주기 어렵다. 또 누구나 투표를 만들 수 있으면 곤란하므로, 투표를 만들고 정리하는 권한은 운영자에게만 있어야 한다.

## Solution

링크 하나로 휴대폰에서 바로 여는 한국어 웹앱. 운영자는 비밀번호로 로그인해 투표(질문 1개 + 선택지 2~10개)를 만들고, 마감하고, 삭제한다. 참여자는 로그인 없이 투표 목록이나 공유받은 링크로 들어가 선택지 하나에 표를 던지고, 표를 던진 뒤 결과를 본다. 한 브라우저에서는 한 투표에 한 표만 던질 수 있고, 마감된 투표의 결과는 누구나 볼 수 있다. Vercel에 배포하고 Neon(Postgres)에 저장한다.

## User Stories

### 참여자 — 투표 찾기

1. As a 참여자, I want 첫 화면에서 투표 목록을 보기, so that 지금 참여할 수 있는 투표를 한눈에 찾을 수 있다
2. As a 참여자, I want 진행 중인 투표가 목록 위쪽에 최신순으로 보이기, so that 참여해야 할 투표를 먼저 볼 수 있다
3. As a 참여자, I want 마감된 투표가 목록 아래쪽에 "마감" 표시와 함께 최신순으로 보이기, so that 지난 투표의 결과를 찾아볼 수 있다
4. As a 참여자, I want 목록에서 투표를 눌러 해당 투표 화면으로 들어가기, so that 바로 표를 던질 수 있다
5. As a 참여자, I want 카톡 등으로 공유받은 투표 링크로 바로 해당 투표에 들어가기, so that 목록을 뒤지지 않아도 된다
6. As a 참여자, I want 존재하지 않거나 삭제된 투표 링크를 열면 "없는 투표"라는 안내를 보기, so that 무엇이 잘못됐는지 알 수 있다
7. As a 참여자, I want 투표가 하나도 없을 때 "아직 투표가 없습니다" 같은 안내를 보기, so that 앱이 고장난 게 아님을 알 수 있다

### 참여자 — 표 던지기

8. As a 참여자, I want 투표 화면에서 질문과 모든 선택지를 만든 순서대로 보기, so that 무엇을 고르는지 정확히 알 수 있다
9. As a 참여자, I want 선택지 하나를 골라 표를 던지기, so that 내 의견을 반영할 수 있다
10. As a 참여자, I want 로그인이나 이름 입력 없이 표를 던지기, so that 부담 없이 빠르게 참여할 수 있다
11. As a 참여자, I want 선택지를 고르지 않고 제출하면 안내를 받기, so that 빈 표가 들어가지 않는다
12. As a 참여자, I want 표를 던진 직후 결과 화면을 보기, so that 다른 사람들의 선택과 비교할 수 있다
13. As a 참여자, I want 이미 표를 던진 투표에 다시 들어가면 투표 폼 대신 결과와 "이미 참여함" 표시를 보기, so that 내가 참여했음을 확인할 수 있다
14. As a 참여자, I want 결과 화면에서 내가 고른 선택지가 표시되기, so that 내 선택을 다시 확인할 수 있다

17. As a 참여자, I want 마감된 투표에서는 투표 폼 대신 "마감됨" 안내와 결과를 보기, so that 더 이상 참여할 수 없음을 알고 결과는 확인할 수 있다

## Implementation Decisions

### 용어

- 코드와 UI 모두 `CONTEXT.md`의 용어를 따른다: 투표(Poll), 선택지(Option), 표(Vote), 운영자(Admin), 참여자(Voter), 마감(Close), 결과(Result).

### 모듈

- **투표 모듈 (핵심 도메인 모듈)**: 투표에 관한 모든 규칙을 담는 깊은 모듈. 화면·서버 액션은 이 모듈만 호출한다. SQL 실행 함수를 주입받아 동작하며, 운영에서는 Neon(`@neondatabase/serverless`), 테스트에서는 PGlite가 주입된다. 인터페이스(개념 수준):
  - 투표 목록 조회: 진행 중 먼저, 그다음 마감, 각각 최신순. 각 항목에 총 표 수 포함.
  - 투표 만들기(질문, 선택지 목록) → 새 투표 id. 검증 실패 시 어떤 규칙을 어겼는지 구분 가능한 오류.
  - 투표 마감(투표 id). 이미 마감된 투표에 대해서는 변화 없음.
  - 투표 삭제(투표 id). 그 투표의 선택지·표도 함께 삭제.
  - 표 던지기(투표 id, 선택지 id, 참여자 식별자). 거부 사유를 구분: 없는 투표 / 마감된 투표 / 해당 투표에 속하지 않은 선택지 / 이미 표를 던짐.
  - 참여자 관점 투표 조회(투표 id, 참여자 식별자 또는 없음) → 투표 정보, 마감 여부, 참여 여부와 고른 선택지, 결과(공개 조건을 만족할 때만).
  - 운영자 관점 투표 조회(투표 id) → 투표 정보와 결과(항상).
- **운영자 인증 모듈**: DB를 쓰지 않는 순수 모듈.
  - 비밀번호 확인: 환경변수의 운영자 비밀번호와 상수 시간 비교.
  - 세션 토큰 발급: 만료 시각(발급 후 1일)을 담고 서명 키로 HMAC 서명.
  - 세션 토큰 검증: 서명 위조·만료 시 거부.
- **서버 액션 / 라우트 (얇은 층)**: 쿠키를 읽고 써서 참여자 식별자·운영자 세션을 꺼낸 뒤 위 두 모듈을 호출하고, 결과를 화면으로 넘긴다. 운영자 액션은 모두 세션 검증을 먼저 거친다. 비밀번호가 틀리면 응답을 약 1초 지연한다.
- **화면**: 투표 목록(첫 화면), 투표 화면(`/polls/<id>`: 투표 폼 또는 결과), 운영자 로그인·대시보드·투표 만들기(`/admin` 아래).

### 규칙

- 선택지 2~10개. 질문 1~200자, 선택지 각 1~100자(앞뒤 공백 제거 후 기준). 공백 제거 후 같은 선택지 중복 불가.
- 투표는 만든 뒤 수정 불가.
- 마감은 되돌릴 수 없다. 마감된 투표는 표를 받지 않는다.
- 한 참여자 식별자당 한 투표에 한 표. 던진 표는 변경·취소 불가.
- 결과 공개 조건(참여자): 해당 투표에 표를 던졌거나, 투표가 마감됨. 운영자는 항상 볼 수 있다.
- 결과: 총 표 수, 선택지별 표 수와 비율(%), 선택지는 만든 순서 유지. 총 표 수가 0이면 모든 비율 0%.
- 삭제는 하드 삭제이며 선택지·표가 함께 삭제된다.

### 참여자 식별 (ADR-0001)

- 참여자는 로그인하지 않는다. 처음 방문 시 무작위 참여자 식별자를 발급해 오래 유지되는 httpOnly 쿠키에 저장한다.
- 시크릿 창·다른 기기·쿠키 삭제로 다시 투표할 수 있다는 한계는 받아들인 것이다.

### 운영자 인증

- 운영자 비밀번호는 하나를 공유하며 환경변수 `ADMIN_PASSWORD`에 둔다(16자 이상 무작위 권장).
- 세션은 서명된 httpOnly 쿠키, 유효기간 1일. 서명 키는 별도 환경변수(`SESSION_SECRET`).
- 로그아웃은 세션 쿠키 삭제.

### 스키마 (`schema.sql`)

- **polls**: id(무작위 문자열, URL에 노출), 질문, 생성 시각, 마감 시각(마감 전에는 비어 있음 — 마감 여부는 이 값으로 판단).
- **options**: id, 소속 투표 id(투표 삭제 시 함께 삭제), 내용, 순서 번호. (투표 id, 순서 번호) 유일.
- **votes**: id, 투표 id(투표 삭제 시 함께 삭제), 선택지 id, 참여자 식별자, 생성 시각. **(투표 id, 참여자 식별자) 유일 제약**으로 한 표 규칙을 DB에서도 보장한다(동시 제출 경쟁 상태 방지).
- 표의 선택지가 같은 투표에 속하는지는 투표 모듈에서 검증한다.

### 인프라

- Next.js 16 App Router, Vercel 배포. 구현 전 `node_modules/next/dist/docs/`의 해당 가이드를 확인한다(이 버전은 기존 지식과 다를 수 있음).
- DB 접근은 ORM 없이 `@neondatabase/serverless`로 SQL 직접 작성.
- Neon 브랜치: `main`(배포, Vercel 연결), `dev`(로컬, `.env.local`의 `DATABASE_URL`).
- 환경변수: `DATABASE_URL`, `ADMIN_PASSWORD`, `SESSION_SECRET`.
- 결과는 요청 시점 기준으로 렌더링한다(캐시로 오래된 결과가 보이지 않게). 실시간 자동 갱신은 없다.

## Testing Decisions

- 좋은 테스트는 모듈의 공개 인터페이스를 통해 **외부에서 관찰되는 동작**만 검증한다. SQL 문장, 테이블 내부 구조, 함수 호출 순서 같은 구현 세부는 검증하지 않는다. 구현을 바꿔도 동작이 같으면 테스트는 그대로 통과해야 한다.
- 테스트 도구: Vitest. 새 개발 의존성 `vitest`, `@electric-sql/pglite`.
- **투표 모듈 (핵심 테스트 경계)**: 실제 Postgres 동작을 위해 PGlite(인메모리 Postgres)에 운영과 같은 `schema.sql`을 적용하고, 테스트마다 새 DB로 시작한다. DB를 모킹하지 않는다. 검증 대상:
  - 선택지 개수(1개·11개 거부, 2개·10개 허용), 질문·선택지 길이, 빈 값, 공백 제거 후 중복 거부
  - 한 참여자 식별자당 한 표(두 번째 표 거부), 다른 식별자는 각각 허용
  - 마감된 투표에 던진 표 거부, 마감 후 결과 유지
  - 다른 투표의 선택지로 던진 표 거부, 없는 투표에 던진 표 거부
  - 결과 공개 조건: 미참여·진행 중이면 결과 없음, 참여 후 결과 있음, 마감 후 미참여자도 결과 있음, 운영자 조회는 항상 결과 있음
  - 결과 집계: 표 수·비율·만든 순서 유지, 0표일 때 0%
  - 목록 정렬: 진행 중 먼저·마감 나중, 각각 최신순, 총 표 수
  - 삭제 후 목록·조회에서 사라짐
- **운영자 인증 모듈**: 순수 함수 단위 테스트. 올바른/틀린 비밀번호, 유효한 토큰 통과, 위조된 서명 거부, 1일 경과 토큰 거부(시각 주입).
- **테스트하지 않는 것**: 화면 컴포넌트, 서버 액션(얇은 연결층), 쿠키 입출력 연결부, 1초 지연.
- 선행 사례: 저장소에 기존 테스트가 없다. 이 스펙의 테스트가 첫 사례가 된다.

## Out of Scope

- 참여자 로그인·계정, 이름/학번 입력
- 쿠키 우회(시크릿 창·다른 기기)에 대한 추가 방어
- 여러 운영자 계정, 운영자별 권한, 계정 관리 화면
- IP 기반 로그인 잠금, 외부 레이트 리밋 저장소
- 투표 수정, 표 변경·취소, 마감 되돌리기
- 마감 시각 예약(자동 마감)
- 복수 선택, 순위 투표, 자유 응답, 익명/기명 설정
- 한 투표에 여러 질문
- 실시간 결과 자동 갱신
- 결과 내보내기(CSV 등), 알림
- 화면 E2E 테스트
- 다국어 지원(한국어만)
