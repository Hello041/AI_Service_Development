# 02: 투표 만들기와 목록 보기

**What to build:** 로그인한 운영자가 질문 1개와 선택지 2~10개로 투표를 만들고, 만든 직후 그 투표의 공유 링크를 얻는다. 참여자는 첫 화면의 투표 목록에서 투표를 보고, `/polls/<id>`로 들어가 질문과 선택지를 만든 순서대로 본다(표 던지기는 03에서). 투표가 없으면 빈 목록 안내가, 없는 투표 링크에는 "없는 투표" 안내가 나온다.

스펙: `.scratch/voting-app/spec.md` (투표 모듈, 규칙, 스키마). 용어는 `CONTEXT.md`를 따른다.

**Blocked by:** 01 (운영자 로그인·로그아웃)

**Status:** ready-for-agent

- [ ] `schema.sql`에 polls(무작위 id, 질문, 생성 시각, 마감 시각), options(소속 투표·내용·순서, 투표 삭제 시 함께 삭제) 정의
- [ ] 투표 모듈이 SQL 실행 함수를 주입받는다: 운영에서는 `@neondatabase/serverless`(`DATABASE_URL`), 테스트에서는 PGlite
- [ ] PGlite 테스트 환경: 테스트마다 `schema.sql`을 적용한 새 DB
- [ ] 투표 만들기 검증: 선택지 2~10개, 질문 1~200자, 선택지 1~100자(앞뒤 공백 제거 후), 공백 제거 후 중복 선택지 거부. 어떤 규칙을 어겼는지 구분 가능한 오류
- [ ] 운영자 투표 만들기 화면: 선택지 입력칸 추가·제거, 검증 실패 시 입력 유지, 성공 시 공유 링크 표시
- [ ] 투표 만들기는 운영자 세션이 있어야만 가능하다
- [ ] 투표 id는 추측하기 어려운 무작위 문자열이다
- [ ] 첫 화면: 투표 목록(최신순), 비었을 때 안내
- [ ] `/polls/<id>`: 질문과 선택지를 만든 순서대로 표시, 없는 id면 "없는 투표" 안내
- [ ] 투표 모듈 테스트: 선택지 개수 경계(1·2·10·11), 길이·빈 값·중복 검증, 만든 투표가 목록과 조회에 순서대로 나옴
- [ ] 결과는 요청 시점 기준으로 렌더링된다(오래된 캐시 없음)
